# Plan 02-02: Employee Directory, Profiles, Reporting Hierarchy & Status Lifecycle Engine

**Phase:** 02 — Organization Hierarchy, Employee Management & Cloud Storage  
**Status:** Completed  

## Objective
Implement comprehensive employee lifecycle management: multi-role directory queries respecting data scopes, employee creation with automatic user account provisioning, reporting line hierarchy validation, and status lifecycle state transitions with automated notification triggers.

## Tasks
1. **Employee Management Service**:
   - `GET /api/v1/employees` — Scoped list (filters: department, team, status, search keyword).
   - `POST /api/v1/employees` — Onboard new employee: creates User + Employee + default LeaveBalances + EmployeeShift.
   - `GET /api/v1/employees/:id` — Detailed profile with emergency contacts, reporting line, and documents.
   - `PATCH /api/v1/employees/:id` — Update employee demographic and job information.
   - `GET /api/v1/employees/:id/org-chart` — Subtree of direct and indirect reportees.
2. **Status Lifecycle & Automated Alerts**:
   - `PATCH /api/v1/employees/:id/status` — Status transition (`ACTIVE`, `ON_PROBATION`, `SUSPENDED`, `ON_LEAVE`, `RESIGNED`, `TERMINATED`).
   - Audit trail creation in `AuditLog` for every status change.
   - Automated notification triggers:
     - Notification record created in `Notification`.
     - Email dispatched to employee and reporting manager.
     - Account login lock when transitioning to `SUSPENDED` or `TERMINATED`.
3. **Emergency Contacts CRUD**:
   - `POST /api/v1/employees/:id/emergency-contacts`
   - `GET /api/v1/employees/:id/emergency-contacts`
   - `DELETE /api/v1/employees/:id/emergency-contacts/:contactId`
4. **Unit & Integration Tests**:
   - Test employee creation with user account linkage.
   - Test reporting hierarchy validation (prevent circular references).
   - Test status transition and notification dispatch.
   - Test data scope filtering on employee directory.
