# Plan 06-02: 3-Day Stripe Retry Logic, 2-Month Non-Payment Lockout & Audit Log

**Phase:** 06 — Subscriptions, Gemini AI Assistant & Security Hardening  
**Status:** In Progress  

## Objective
Implement BullMQ / scheduled retry logic for failed payments (Day +1, +2, +3 with exact error logging), 2-month non-payment lockout (`Suspended (Non-Payment)`), and security audit log recording.

## Tasks
1. **Renewal Retry & Lockout Cron (`SubscriptionCronService`)**:
   - `handleRenewalRetries()`:
     - Detects subscriptions with status `PAST_DUE`.
     - Logs exact failure reason (`lastFailedReason`).
     - Triggers automated retry or warning emails to Company Admin on Day +1, +2, and +3.
   - `handleNonPaymentLockout()`:
     - Detects companies where `lastFailedPaymentAt` is older than 60 days (2 months).
     - Transitions `Company.status = SUSPENDED` with reason `Suspended (Non-Payment)`.
     - Emits `NotificationType.SUBSCRIPTION_SUSPENDED`.
2. **Security Audit Log (`AuditLogService`)**:
   - Central audit logging method: `logSecurityEvent(companyId, userId, action, resource, details, ipAddress)`.
   - Records authentication anomalies, role upgrades, salary modifications, and status changes.
3. **Unit Tests**:
   - `subscription-cron.service.spec.ts`: Tests 3-day retry detection and 60-day lockout company suspension.
   - `audit-log.service.spec.ts`: Tests security audit record generation.
