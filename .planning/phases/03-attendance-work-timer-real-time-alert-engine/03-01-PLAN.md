# Plan 03-01: Attendance Core, Remote Permissions & HR Exceptions Queue

**Phase:** 03 — Attendance, Work Timer & Real-Time Alert Engine  
**Status:** Completed  

## Objective
Implement attendance check-in/out endpoints (onsite and remote), standing remote work permission request/approval workflow, and the HR Exceptions Queue for reviewing unauthorized remote check-ins.

## Tasks
1. **Attendance Check-in / Checkout**:
   - `POST /api/v1/attendance/check-in`:
     - Accepts `isRemote: boolean`, optional `location: { lat, lng }`, client IP.
     - Onsite: Marks `PRESENT`, logs IP and location.
     - Remote: Verifies active `RemoteWorkPermission`.
       - If authorized -> `PRESENT_REMOTE`.
       - If unauthorized -> `ABSENT_PENDING_REVIEW`, creates exception alert for HR Manager.
   - `POST /api/v1/attendance/check-out`:
     - Calculates `workMinutes` and `overtimeMinutes`.
     - Updates check-out timestamp.
   - `GET /api/v1/attendance/today`: Current user's daily status.
   - `GET /api/v1/attendance/records`: Scoped attendance history (date range, department, employee).
2. **Standing Remote Work Permissions**:
   - `POST /api/v1/attendance/remote-permissions`: Request remote work standing approval.
   - `PATCH /api/v1/attendance/remote-permissions/:id/step1`: Team Lead approval.
   - `PATCH /api/v1/attendance/remote-permissions/:id/step2`: Dept Manager final approval.
   - `GET /api/v1/attendance/remote-permissions`: Scoped listing of standing permissions.
3. **HR Exceptions Queue**:
   - `GET /api/v1/attendance/exceptions`: List all `ABSENT_PENDING_REVIEW` records.
   - `POST /api/v1/attendance/exceptions/:id/resolve`: HR Manager approves (sets `PRESENT_REMOTE`) or rejects (sets `ABSENT`).
4. **Unit & Integration Tests**:
   - Onsite check-in test.
   - Authorized remote check-in test.
   - Unauthorized remote check-in routed to HR Exceptions test.
   - HR exception resolution test.
